# ¿Qué Onda?

Chilean news aggregator + live TV/radio streaming in a single-page, ad-free dashboard.

## Stack

- Astro 7 (SSR) + React 19 + TypeScript + Tailwind CSS 4 + DaisyUI v5
- Font: `Figtree` (body/headings) + `DM Serif Display` (hero), loaded non-blocking via Google Fonts `<link>`.
- Icons: inline SVGs (no icon library). No animation library — CSS transitions + `active:scale` only.
- Sound: Web Audio API singleton (`src/lib/sound.ts`) — triangle wave + bandpass noise, lazy AudioContext.
- Deploy: Cloudflare Pages Functions (SSR), `nodejs_compat`, `@astrojs/cloudflare` v14+ `mode: 'directory'` + `scripts/post-build-pages.mjs` post-build hook.
- Build: `npm run build && node scripts/post-build-pages.mjs`. Dev `npm run dev`. Regenerators: `npm run update-feeds` | `update-stops` | `update-holidays`.

## Architecture Notes

- Astro SSR serves only the shell — every widget fetches client-side via `fetch('/api/...')` or directly from CORS-enabled external APIs.
- **Two-tier cache**: server-side edge cache (`Cache-Control` + Cloudflare Cache API via `caches.default` + dedupe) + client IDB (instant reload). Server pre-warming via inline `requestIdleCallback` script on page load.
- **IDB pattern** (per widget): render from IDB → background fetch → update IDB → server cache hit.
- Hydration tiers:
  - `client:load`: Header, SideIndex, EmergencyTicker, EmergencyWidget, Footer.
  - `client:idle`: ClientNewsFeed, ClientTV, ClientRadios, FinanceWidget, YouTubeTrends, SpotifyChart, GoogleTrendsWidget, WeatherWidget, TransportWidget, FootballTable, JobList, HolidaysWidget, FiestasCountdown.
- `client:isidle` deferred single delegated share handler: `SectionShareHandler` wires every `[data-section-share]` button to the section anchor share + status toast (one island, zero per-section hydration).
- `clustering.ts` code-split via dynamic `import()` in ClientNewsFeed (separate ~2.8 KB chunk); shared by server-side clustering in the article reader.
- `hls.js` dynamically imported only on user play for m3u8 streams (TV + radio); iframes used for YT/Twitch.

## Theme System

- 35 DaisyUI v5 themes in `src/styles/global.css` (`dark --default` default). `data-theme` on `<html>` set by init script + `ThemeSwitcher`, persisted in `localStorage.theme`.
- Semantic DaisyUI classes (`bg-base-100..300`, `text-base-content[/70/50]`, `text-primary`, `bg-primary`, `text-primary-content`).
- `accent` is never used. Translucent primary = `bg-primary/*` + `text-primary`. `.light-theme` class (not `@media color-scheme`) for light-theme CSS.

## Accessibility

Native elements first, visible `focus-visible` rings (`outline-2 outline-offset-2 outline-primary`), keyboard operable, skip link (`href="#main"`), `aria-live="polite"` for auto-updating emergency, `prefers-reduced-motion` respected on marquee/pulse. Modal/overlay a11y: `role="dialog"` + `aria-modal` + focus trap + restore.

## API Endpoints (all JSON, 15-min default unless noted; per-source where noted)

- `GET /api/news?mode=inventory` — OPML source list (server 15 min)
- `POST /api/news/batch` — per-source RSS (server `rss:{url}` 15 min; IDB 10 min)
- `GET /api/channels?category=&source=json-teles|iptv-org` — TV channels (server 1 h; IDB 24 h). Used by ClientTV (CORS-free).
- `GET /api/finance` — UF/USD/EUR/IPC/UTM merge chain: mindicador → Boostr → Findic → SII RSS → DolarAPI (server 30 min). FinanceWidget also fetches dolarapi/mindicador client-side as primary.
- `GET /api/youtube` — YouTube Chile RSS via channel feeds (server 60 min); `GET /api/youtube/source` retries a single channel (server 5 min)
- `GET /api/trends` — Google Trends Chile RSS (server 30 min)
- `GET /api/weather?city=|city=&cities=&q=` — Open-Meteo → Gael Cloud → Boostr → stale cache fallback chain (server 10 min). WeatherWidget also fetches Open-Meteo directly as primary + DMC forecast.
- `GET /api/transport?city=&stop=|route=|mode=route-names` — Metro.cl status + RED bus predictions + stops from DTPM GTFS `stops-database.json` (server 5 min)
- `GET /api/sports` — sports RSS (OPML sports category + keyword-matched) (server 30 min)
- `GET /api/futbol` — standings+maches via ESPN client-side; RSS articles via server (server 10 min articles)
- `GET /api/emergency` — sismos: Gael Cloud → Boostr → USGS (|mag≥5.0) (server 5 min); `senapred[]` = official Telegram SAE alerts (parsed, client-side coord enrichment from Boostr if server-side unreachable)
- `GET /api/power` — POST proxy to SEC clientes sin suministro; comunas via `comunas-coords.ts`; hourly series (server 15 min)
- `GET /api/holidays` — nager.at (server 30 min; bundled fallback `holidays.json` from `update-holidays-db`)
- `GET /api/radio-stations` — radio-browser.info → json-teles → FALLBACK_RADIOS (server 1 h; IDB 24 h)
- `GET /api/article?url=` — cheerio content proxy (server 60 min per URL)
- `GET /api/jobs` — getonbrd/Remotive/workanywhere (server 1 h)
- `GET /api/spotify` — Spotify Top 50 Chile iframe source (server 30 min)
- `GET /api/forecast` — DMC pronóstico.js 5-day parse (server 1 h)
- `GET /api/cron` — Bearer-auth cache pre-warming (sports, youtube, trends)

### Data Source fallback chains

Weather: Open-Meteo → Gael Cloud → Boostr → stale cache → null.
Emergency: Gael Cloud → Boostr → USGS (≥5.0). SENAPRED SAE: official Telegram feed (separate).
Finance: merge across mindicador → Boostr → Findic → SII RSS → DolarAPI.
Radio: radio-browser.info → json-teles(cl music only) → FALLBACK_RADIOS.
Feeds DB: `feeds-database.json` (build-time) → GitHub raw → jsDelivr (fire-and-forget background refresh in `loadFeedsDatabase`).
TV: json-teles → jsDelivr; YouTube: channel RSS from json-teles; Holidays: nager.at → bundled JSON.

## News System

- 6 default slots; persisted to `localStorage['news-slots']` (sourceKeys). Pinned sources `localStorage['news-pins']` (`Record<slotIndex, {sourceKey,name,url}>`, sourceKey only one slot at a time).
- No "Phase 3": clustering + trending computed client-side from the 6 active sources.
- Source dropdown per slot; in-use sources disabled elsewhere. `?tag=` URL param filters clusters + slots; "Limpiar filtro" always available when a tag is active (TrendingTags renders even when tag list is empty).
- Clustering: keyword unigrams/bigrams/trigrams (stopwords removed) + Jaccard similarity (>0.25 = same cluster), sorted by count × source diversity.
- Trending tags clickable → sets `?tag=` + scrolls to news.
- Server per-source cache `rss:{url}` (15 min); client batch cache `news-batch:{keys}` (IDB 10 min); per-source `news-source:{key}` (IDB).

## TV & Radio Systems

TV: single `<video>` + one hls.js instance shared by inline and PiP; FLIP on mode switch; auto-PiP via IntersectionObserver; search + localStorage favorites; signal selector HD/WEB/YT/Twitch.
Radio: boombox layout, hidden `<video>` + hls.js for HLS, `<audio>` for direct; CD-disc visuals.
Both fetch channel/station lists via server endpoints (CORS-free); IDB 24 h fallback to hardcoded lists.

## Sound System

`src/lib/sound.ts` singleton: `play(role)`, `toggleMuted()`/`isMuted()`, `setVolume()`/`getConfig()`, `setMuted()`, `cleanup()`. 20 roles (interaction.*, navigation.*, notification.*, overlay.*, media.*, hero.*). Footer sound toggle persists via module state. Mute defaults from `localStorage` (footer button writes it).

## Layout & Shared Components

- `Header` (fixed, hides on down-scroll), `SideIndex` (vertical section index), `Footer` (image credit + sound toggle), `Section` (letter-by-letter animated title + inline icon share button), `SectionShareHandler` (delegated section-anchor share), `BackToTop` (fixed, lifts above footer credits when near bottom), `ShareButton` (navbar: native share on touch / clipboard on desktop), `Emoji.tsx`.
- Section attribution: right-aligned `Fuente:` / `Fuentes:` with links to primary + fallbacks (e.g. emergency = Gael → Boostr → USGS).

## Conventions

- Named React exports, `.tsx`, Tailwind classes. `client:*` directives respected.
- Every section renders source attribution bottom-right (`Fuente:` with links).
- `ponytail:` comments mark deliberate simplifications (e.g., cacheGet no-TTL stale-first, 3 s IDB race guard).
